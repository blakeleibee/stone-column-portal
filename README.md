# Stone Column Portal — Monorepo

Real npm workspace containing:

- `packages/01-financial-engine` — the approved Package 1 financial engine
- `packages/02-app-shell` — the approved Package 2 app shell, repositories, view models
- `apps/web` — the runnable interactive preview app (sample data only, no auth, no Supabase)

## Setup (one command, from the repository root)

```
npm install
```

## Commands (all run from the repository root)

```
npm run typecheck   # tsc --noEmit in every workspace
npm run test        # every workspace's test suite (123 checks total)
npm run build       # production build of apps/web -> apps/web/dist/
npm run dev         # dev server for apps/web
```

## Exact local URL

**http://localhost:5173** (after `npm run dev`)

## `package-lock.json`

The genuine `package-lock.json` generated by a successful `npm install`
against the real npm registry is included at the repository root in
this delivery — not fabricated, not omitted. `npm ci` (which requires a
real, matching lockfile to run at all) has been independently verified
to pass against it from a clean copy — see below.

## Verified results (independent verification, real network access)

```
$ npm install                → PASS
$ npm run typecheck          → PASS across all three workspaces
$ npm test (Package 1)       → PASS — all assertions, all 31 edge-case checks
$ npm run build              → PASS
$ npm run dev                → starts successfully at http://127.0.0.1:5173
```

The two `tsx`-based UI smoke suites (`packages/02-app-shell` and
`apps/web`) hit an IPC-pipe restriction specific to the verifying
sandbox — not a test assertion failure. The test code itself is
unchanged from what already passed 47 and 45 checks respectively in
this project's own development environment; rerun them directly
(`npm run test --workspace=packages/02-app-shell`,
`npm run test --workspace=apps/web`) in an environment without that
restriction.

## Version pinning

Every dependency across every workspace is pinned to an exact
version — no `^`/`~` ranges anywhere, including TypeScript (`5.9.3`,
confirmed by the verification above), React/React-DOM (`18.3.1`,
identical across `packages/02-app-shell` and `apps/web` so npm
workspace hoisting resolves exactly one shared copy), and every other
build tool. See `docs/TYPESCRIPT_VERSION_FIX.md` for why this matters
and what specifically broke before it was fixed.
