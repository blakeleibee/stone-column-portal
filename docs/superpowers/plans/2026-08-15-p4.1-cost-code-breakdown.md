# P4.1 — Cost Code Breakdown (Child Budget Items) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Design record (read first, authoritative for every "why"):**
`docs/production-build/P4.1-DESIGN.md`. This plan implements that design
exactly — 10 decisions, no redesign. Owner has not yet approved either
document; do not begin any task in this plan until the owner explicitly
approves `P4.1-DESIGN.md` AND explicitly says to begin implementation.

**Goal:** Let every project cost code optionally carry project-specific
child budget breakdown rows, with the parent remaining the sole
QuickBooks-mapped entity and its rolled-up totals computed with zero
changes to the formula that already computes them.

**Architecture:** One new table, `cost_code_children`, composite-FK'd to
`(cost_code_id, project_id)` exactly like `cost_codes` itself. One new
nullable, composite-FK'd `cost_code_child_id` column added to six
existing tables (`budget_ledger`, `expenses`, `committed_costs`,
`forecast_entries`, `bid_packages`, `material_order_line_items`) — no
new financial model, no backfill, every pre-existing row is implicitly
"Unallocated" (`cost_code_child_id is null`) with zero UPDATEs. Two P5
RPCs (`award_bid()`, `commit_material_order()`) forward the new column;
one P4 trigger (`enforce_single_original_budget_entry`) is widened to
scope by the `(cost_code_id, cost_code_child_id)` pair. The financial
engine's `computeCategoryFinancials()` is internally refactored (never
its external signature) to share its summation logic with a new
`computeChildBreakdown()`, so a parent's rollup is provably identical
before and after this package by construction, not by re-testing luck.

**Tech Stack:** Same as P4/P5 — Next.js 14.2.35 App Router, Supabase
Postgres/RLS, `packages/01-financial-engine` (pure TS).

## Global Constraints

- Money is always an integer number of cents. Never a float. (CLAUDE.md)
- No screen computes its own financial numbers — everything goes
  through `packages/01-financial-engine`. (CLAUDE.md)
- Nothing is silently overwritten, merged, or recalculated. Corrections
  are new ledger rows with a reason, not edits — unaffected by this
  package, but every new write path added here (child create/rename/
  archive/reorder) still respects it: renaming or reordering a child is
  a plain field update on the child row itself (not a financial fact),
  never a ledger row.
- Never edit `schema/001`–`015` in place. All P4.1 schema changes are
  additive, in a new `schema/016_cost_code_children.sql` (+ down) file
  only, mirrored into `supabase/migrations/`.
- Every mutation runs through the caller's own JWT-bearing Supabase
  client (RLS-scoped) via a Server Action — never a client-side browser
  call to Supabase, never the service-role client.
- Business logic lives in a plain service function under
  `packages/02-app-shell/src/services/`; any Server Action is a thin
  adapter only.
- A child is project-specific breakdown detail — never a new global
  cost code, never QuickBooks-item-mapped, never seeded by any cost
  code template. (P4.1-DESIGN.md Decision 1)
- `cost_code_child_id` is nullable everywhere it's added, and existing
  rows are never backfilled — "Unallocated" is the implicit state of
  every pre-existing row, not a value anyone writes. (Decision 2)
- Delete is rejected (not silently converted to archive) if any
  financial row references a child; archive is always available.
  Modeled directly on `cost_codes`' own
  `reject_cost_code_delete_if_used()` (schema/001). (Decision 3)
- A child's name is unique among *active* siblings only (partial
  unique index), never table-wide — an archived name may be reused.
  (Decision 4)
- `enforce_single_original_budget_entry` scopes by
  `(cost_code_id, cost_code_child_id)` using `is not distinct from`
  semantics for the nullable column — a parent-level original entry and
  each child's original entry are independent, not mutually exclusive.
  (Decision 5)
- QuickBooks import (`parseQuickBooksCsv.ts`, `confirm_import_batch()`,
  `import_mapping_profiles`) is never modified — it keeps resolving to
  `cost_code_id` only. Manual post-import child assignment is a
  separate, new, small write path. (Decision 6)
- Client-facing budget screens (`ClientBudgetAndInvoicesScreen.tsx`)
  are out of scope for this package — parent-level only, unchanged.
  (Decision 7)
- `material_orders.cost_code_id` (the order-level convenience default)
  does **not** get a matching `cost_code_child_id` — only
  `material_order_line_items` (the authoritative grain) does. (Decision 8)
- `computeCategoryFinancials()`'s external signature, inputs, and
  outputs must remain byte-identical to its pre-P4.1 form — proven by
  re-running its own existing test suite completely unmodified.
  (Decision 9)
- A bid package supports at most one child target
  (`bid_packages.cost_code_child_id`, single nullable column), matching
  its existing single-cost-code shape one level deeper — never a
  line-item table. (Decision 10)
- `npm run typecheck` / `npm run test` / `npm run build` must pass
  after every task.
- Do not touch P5 Tasks 7–9 (`/admin/commitments`, procurement
  services, `/admin/procurement`) — those tasks resume, informed by
  this package's finished schema, only after this plan's own closeout.

```sql
-- =====================================================================
-- Stone Column Portal — Migration 016: cost code children (project-
-- specific budget breakdown rows under a canonical parent cost code).
-- See docs/production-build/P4.1-DESIGN.md for full rationale.
-- =====================================================================

create table cost_code_children (
  id                uuid primary key default uuid_generate_v4(),
  project_id        uuid not null references projects(id) on delete cascade,
  cost_code_id      uuid not null,
  name              text not null,
  scope_description text,
  sort_order        integer not null default 0,
  is_archived       boolean not null default false,
  created_by        uuid references profiles(id),
  created_at        timestamptz not null default now(),

  constraint cost_code_children_cost_code_project_fk
    foreign key (cost_code_id, project_id) references cost_codes(id, project_id),
  unique (id, cost_code_id, project_id)
);

create unique index cost_code_children_name_unique_active
  on cost_code_children (cost_code_id, name) where not is_archived;

alter table cost_code_children enable row level security;

create policy cost_code_children_staff_full_access on cost_code_children
  for all to authenticated
  using (is_org_staff(project_id)) with check (is_org_staff(project_id));

create trigger audit_cost_code_children after insert or update or delete on cost_code_children
  for each row execute function public.log_audit();

create or replace function public.reject_cost_code_child_delete_if_used() returns trigger
language plpgsql
set search_path = public, pg_temp
as $$
begin
  if exists (select 1 from public.budget_ledger where cost_code_child_id = OLD.id)
     or exists (select 1 from public.expenses where cost_code_child_id = OLD.id)
     or exists (select 1 from public.committed_costs where cost_code_child_id = OLD.id)
     or exists (select 1 from public.forecast_entries where cost_code_child_id = OLD.id)
     or exists (select 1 from public.bid_packages where cost_code_child_id = OLD.id)
     or exists (select 1 from public.material_order_line_items where cost_code_child_id = OLD.id)
  then
    raise exception 'Cost code child % is in use and cannot be deleted. Archive it instead (is_archived = true).', OLD.id;
  end if;
  return OLD;
end;
$$;

create trigger cost_code_children_no_delete_if_used before delete on cost_code_children
  for each row execute function public.reject_cost_code_child_delete_if_used();
```

```sql
create or replace function public.enforce_single_original_budget_entry() returns trigger
language plpgsql
as $$
begin
  if new.entry_type = 'original' and exists (
    select 1 from public.budget_ledger
    where cost_code_id = new.cost_code_id
      and cost_code_child_id is not distinct from new.cost_code_child_id
      and entry_type = 'original'

    raise exception 'Cost code % (child %) already has an original budget entry — use an adjustment (correction) instead.',
      new.cost_code_id, coalesce(new.cost_code_child_id::text, '<unallocated>');
  end if;
  return new;
end;
$$;
```

```sql
create or replace function public.award_bid(p_bid_submission_id uuid)
returns uuid
language plpgsql security invoker set search_path = public, pg_temp
as $$
declare
  v_submission bid_submissions%rowtype;
  v_package bid_packages%rowtype;
  v_committed_cost_id uuid;
begin
  select * into v_submission from bid_submissions where id = p_bid_submission_id for update;
  if not found then
    raise exception 'Bid submission % not found', p_bid_submission_id;
  end if;
  if v_submission.status <> 'submitted' then
    raise exception 'Bid submission % must be in status ''submitted'' to award (currently %)',
      p_bid_submission_id, v_submission.status;
  end if;

  select * into v_package from bid_packages where id = v_submission.bid_package_id for update;

  insert into committed_costs (project_id, cost_code_id, cost_code_child_id, vendor_name, amount_cents, source_type, source_id)
  select bp.project_id, bp.cost_code_id, bp.cost_code_child_id, v.name, v_submission.amount_cents, 'bid_award', v_submission.id
  from bid_packages bp join vendors v on v.id = v_submission.vendor_id
  where bp.id = v_package.id
  returning id into v_committed_cost_id;

  update bid_submissions set status = 'awarded' where id = v_submission.id;
  update bid_submissions set status = 'declined'
    where bid_package_id = v_package.id and id <> v_submission.id and status = 'submitted';
  update bid_packages set status = 'awarded' where id = v_package.id;

  return v_committed_cost_id;
end;
$$;
```

- [ ] **Step 6: `commit_material_order()` (schema/015) — signature change, deepened grouping**

```sql
create or replace function public.commit_material_order(p_material_order_id uuid)
returns table(cost_code_id uuid, cost_code_child_id uuid, committed_cost_id uuid)
language plpgsql security invoker set search_path = public, pg_temp
as $$
declare
  v_order material_orders%rowtype;
  v_vendor_name text;
  v_line record;
  v_new_committed_cost_id uuid;
  v_line_item_count integer;
begin
  select * into v_order from material_orders where id = p_material_order_id for update;
  if not found then
    raise exception 'Material order % not found', p_material_order_id;
  end if;
  if v_order.status <> 'draft' then
    raise exception 'Material order % must be in status ''draft'' to commit (currently %)',
      p_material_order_id, v_order.status;
  end if;

  select count(*) into v_line_item_count from material_order_line_items where material_order_id = v_order.id;
  if v_line_item_count = 0 then
    raise exception 'Material order % has no line items to commit', p_material_order_id;
  end if;

  select name into v_vendor_name from vendors where id = v_order.vendor_id;

  for v_line in
    select mo_li.cost_code_id as cc, mo_li.cost_code_child_id as ccc,
           sum(mo_li.quantity * mo_li.unit_price_cents)::bigint as total_cents
    from material_order_line_items mo_li
    where mo_li.material_order_id = v_order.id
    group by mo_li.cost_code_id, mo_li.cost_code_child_id
  loop
    insert into committed_costs (project_id, cost_code_id, cost_code_child_id, vendor_name, amount_cents, source_type, source_id)
    values (v_order.project_id, v_line.cc, v_line.ccc, v_vendor_name, v_line.total_cents, 'material_order', v_order.id)
    returning id into v_new_committed_cost_id;

    cost_code_id := v_line.cc;
    cost_code_child_id := v_line.ccc;
    committed_cost_id := v_new_committed_cost_id;
    return next;
  end loop;

  update material_orders set status = 'ordered', ordered_at = now() where id = v_order.id;

  return;
end;
$$;
```

Diff against the real current body in `schema/015` before replacing —
preserve any clause not shown as illustrative above (e.g. if the real
body sets additional columns this excerpt omits). **This is the one
genuine signature break in this migration**; its only intended caller
(P5 Task 8's `procurementService.ts`) does not exist yet, so this has
zero existing call sites to update.
